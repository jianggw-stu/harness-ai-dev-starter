# 工程前置检查与验证

在新增数据字段、外部服务、文档生成、部署拓扑或生产类似行为时使用。

## 前置检查

从代码、脱敏样例、Schema 或用户提供的契约确认相关事实：

- 请求/响应结构、字段类型、空值和一对多关系；
- 展示/持久化值的来源及缺失时的处理；
- 下游服务的职责边界，以及业务逻辑应属于哪一层；
- 涉及媒体/存储时的访问路径、凭据边界和网络链路；
- 运行依赖、版本、字体/浏览器、模板加载和目标环境；
- 高资源操作的并发、超时、清理及错误处理；
- 哪些可观察证据能证明结果正确。

不能只根据字段名推断业务含义。只有缺失信息属于不可替代的业务契约时，才询问用户或报告阻碍；测试图片、加签/加解密样例等可替代输入优先复用仓库资源或自行生成，不要求用户提供整套 Nacos 配置。真实密钥、生产配置和生产数据不得复制进测试产物。

## 验证

- 修改前检查工作区和差异；保护无关变更。
- 将改动限定在用户要求的行为和直接调用链；测试仅覆盖本次改动及直接回归，不顺手修复或测试无关问题。评审发现的外围风险先单独报告，不能自动扩成新功能或架构改造；只有它会使本次验收失败或直接造成数据错误时才纳入本次修复。
- **先锁定本次范围再开发和测试。** 协调者先把用户确认的 Bug/需求写成最小验收清单，并映射到直接调用链、预计改动文件和对应聚焦用例；实现中若发现必须修改清单外模块，先说明该模块与 Bug 的直接因果关系，并通过 Harness 请用户决定是否扩范围，不能默默纳入。QA 只运行覆盖清单和本次改动的聚焦用例，不按整个模块或历史风险清单做顺手巡检。Maven `-am` 为构建目标所需 reactor 依赖而编译的上游模块不等于测试覆盖；不得为它们额外执行测试。若构建被清单外源码错误阻断，记录首个错误并交 Harness 决策，不修改该模块或扩测来消除阻断。
- 对用户指定忽略的旧链路只做必要的只读辨识；不得修改其代码、表结构、数据或调用关系。新功能必须落在用户指定的现行链路中。
- 为变更行为补充或更新聚焦测试，覆盖相关空值和边界场景。
- 测试前简要告知针对性用例、数据和预期。仓库 `AGENTS.md`、项目测试文档或用户指令明确要求的验收直接执行，不再等待二次确认；仅对规则未要求、且会扩大到高成本、共享环境或外部系统的额外集成测试，先与用户确认范围和时机。结束后展示逐项结果、命令/环境、未执行项及阻断，不能只报告汇总数字。
- RocketMQ、Dify、Redis、ES、HTTP 等外部依赖按约定默认正常，完全排除在本阶段 QA 的测试目标、testCases、结果和阻断说明之外；不连接、不索要外部返回或报告“未验证”。隔离本地入口所需的 stub/mock 仅为测试实现细节，不列为测试目标或证据。
- 本机 Harness/Orca 统一调用本 Skill 的 `scripts/mvn-verified.sh`，固定 Maven 3.8.6、JDK 11.0.22、settings、本地仓库与 nexus-private。脚本每次校验版本和路径，默认离线及 `-Dmaven.compiler.useIncrementalCompilation=false`；不再反复从 PATH、IDEA 或 ~/.m2 重新发现配置，也不使用仓库内另一套包装脚本。用户明确更改工具链时才更新固定值；配置校验失败回 Harness，不切换默认配置。POM 插件缺 version 的 WARNING 属于项目告警，不能据此认定 Maven 版本错误或重装工具链。
- 这项核验是 Worker 构建/测试的开工硬门：协调者先核定并记录 `MAVEN_BIN`、Maven 版本、`JAVA_HOME`/Java 版本、settings、本地仓库、离线脚本是否存在，再把这些绝对路径和可直接执行的命令写进 Worker 任务。不得只要求 Worker“自行发现工具链”，也不得由 Worker 按 PATH、Maven 默认 settings 或 `~/.m2/repository` 选择替代配置。
- 开发和返修 Worker 只完成生产代码、格式化与最小模块增量 `compile`，不运行行为测试、Docker 验收、`test-compile` 或重复 QA 用例；测试代码和执行交给独立 QA，用户另有明确要求时除外。最后一次源码修改后执行仓库 `./format`，再用固定脚本运行 `compile -pl <本次模块> -DskipTests`；不得先报告完成再补编译。若编译报错，先区分本次源码错误与依赖 JAR/源码版本不一致；仅在直接依赖确实缺失或过期时定向 `install -pl <依赖模块> -DskipTests` 一次，不能用全仓或反复 -am 遮掩问题。开发只报告“编译通过”，不报告“测试通过”；QA 负责行为测试和业务表验收。
- **开发与 QA 复用同一 worktree、固定脚本、本地仓库和 target 产物。** 派发命令直接给出最小模块及已确认验收编号。开发回报 `compile` 的实际命令、版本和结果；QA 在该产物上执行一次聚焦 `test`。两阶段主源码编译结论不一致时先检查命令、模块、依赖来源和源码更新时间，回 Harness 报告差异；不得重复重跑或把未变化的上游模块交开发返修。
- 同一代码轮次的固定工具链编译已有完整命令、版本、路径和成功回执时，直接核对并复用，不为复核再派 Worker 或重复编译；缺证据、工具链不符或影响编译的源码变化才补做。
- **合并聚焦用例，修正错误后允许一次定向重跑。** Maven 的 `test` 已包含所需的主源码和测试源码编译；QA 对本轮所有聚焦用例用一次命令执行，不先单独 `test-compile` 再执行 `test`。若编译在 Surefire 前失败，读取该次完整编译错误并定位实际解析到的类签名；禁止仅为取得更多输出，用“不带 `-am`”或其它模块变体重跑同一测试。修正本轮新增测试的编译/夹具错误后，可在原授权和时间预算内对同一模块、同一聚焦用例复跑一次，不必新建授权 Gate；没有修正或新证据时不重复原命令。若失败文件在本次范围内，由实现 Worker 修复；若在范围外且 QA 无权修改，记录为阻断并通过 Harness 让用户决策，不把普通类型错误自动升级成大范围返修。
- **增量和模块范围由脚本守住。** 默认 `maven.compiler.useIncrementalCompilation=false`，按源文件与 class 时间戳复用未变产物；不 clean、不删除 target，不默认 -am/-amd。脚本拒绝无 -pl 的生命周期构建、无具体 -Dtest 的测试，以及带 -am/-amd 的测试；缺失直接依赖先定向准备一次。QA 每个受影响模块用 `test -pl <模块> -Dtest=<聚焦类列表>` 一次运行全部本轮用例，不额外先执行 compile/test-compile。只有改动公开 API、父类型、依赖或生成类型确需重编消费者时，纳入最小受影响消费者，并对这些模块显式使用 `-Dmaven.compiler.useIncrementalCompilation=true` 一次；普通实现改动不另加保守全量验收。增量结果不能替代未执行的调用链验收。
- **对 Java 类型编译错误先核对符号来源。** 编译器提示 `String` 与 `Long` 不匹配时，先检查报错调用、字段声明、导入类，以及 Maven 实际解析到的依赖/反编译签名；仓库源码中的 DTO 与编译期依赖签名不一致时，按依赖/模块来源冲突调查，不能直接塞入 `Long.valueOf` 或把类型转换当成显然安全。记录完整的第一条错误、调用签名和归属范围；只有确认转换符合数据契约且属于授权范围后才修改。
- Worker 报告测试完成后，协调者必须从实际命令/transcript 核对 Maven 版本、Java 版本、`-s`/脚本参数及仓库是否与预检记录一致，并确认 Surefire 实际执行目标用例。任一项不匹配时，不接受该次结果作为验收证据；先纠正工具链，再只重跑受影响的定向命令。重复出现私有依赖缺失时，先在正确的本地仓库核对 POM/JAR，避免在错误仓库反复运行。
- 聚焦测试若失败于 `testCompile`，先读取首个完整编译错误，并在测试源码定位报错行；核对对应类型是否存在、实际 package、当前 import 和测试模块可见依赖。不能把“找不到符号”笼统归因为 Maven/环境问题，也不能只复跑命令。若类型存在于另一 package 且测试缺少 import，明确归因为测试源码编译错误并记录最小修复；缺依赖、生成类型缺失或生产编译错误则分别归因。测试类未成功编译时，Surefire 目标用例执行数为 0，所有依赖这些用例的验收条件均为“未验证/阻断”，不得报告测试通过。按 QA Task 授权修正后，触及 Java 要运行 `./format`，并重跑该聚焦类确认 Surefire 实际执行的用例及结果。
- Maven 报依赖缺失时，先比较实际 Maven 版本、settings、本地仓库路径和缓存来源，并在选定仓库中核对依赖声明及 POM/JAR 是否存在；错误仓库缺少缓存不代表开发仓库也缺依赖。不要在错误的默认仓库上反复重跑，也不要把 IDEA Application 能启动当作本次代码已编译或测试通过。用户明确要求补依赖时，按其授权在项目实际使用的仓库中补齐，并继续运行测试。
- 若 Maven 因环境问题确实无法执行，才用已有依赖 classpath 做定向替代验证：显式重新编译本次修改的源码到隔离输出目录，再运行相关测试；不可直接复用时间早于源码的 `target/classes` 或测试 class。替代验证只证明实际运行的用例，不能表述为 Maven 构建或完整测试通过。
- 先运行与改动对应的定向用例；仅当直接受影响的调用链无法由定向用例覆盖，或项目明确要求时，才扩大到最小受影响模块。无明确理由不运行无关模块或全量套件。运行格式化、定向测试和项目强制验收；如必要扩大后有失败，区分目标用例和其他既有失败，保留具体失败名称与错误。
- 仅当本轮 diff 涉及渲染、导出、上传或图片处理时，才检查对应真实输出；仅填充已有图片/URL 数据时，不启动上传或识别链路。
- QA 开始前按最终 diff 将需求页用例映射到实际修改的方法、分支、字段或填充行为，只覆盖映射范围及直接回归。范围外编号回传 `not_applicable` 并给出 diff 依据；至少一项范围内用例必须有实际通过证据。Harness 将不适用与失败、未完成分开显示。真实 Service/Mapper + Docker MySQL 仅核对本次读写及相关共享表前后值；跨系统共用数据库不要求启动其他系统。
- 测试必须调用既有大入口时，预先列出该次执行路径会用到的协作者；与本次改动无关的结算等协作者仅提供最小测试替身，核对 Mockito 参数、重载和可变参数与真实调用一致，不增加其业务测试。替身未注入、参数不匹配或空指针按夹具问题处理；数据库前后值断言未执行时必须标为未验证。需要真实验证的目标读写仍调用真实 Service/Mapper。
- 外部中间件与服务完全不进入本阶段测试结果或阻断信息；不请求用户提供 Dify/MQ/HTTP 返回样例。需要 stub/mock 时只用于隔离本地代码，不作为测试目标。报告只说明本轮 diff 对应的本地行为及实际数据库覆盖。
- Docker/MySQL 测试开始和结束时都不删表、不清空或删除数据；只新增本次测试专属的唯一记录并留存，用唯一主键/测试标识保证重复运行不冲突。运行前核对测试代码没有对共享 schema 执行 `DROP DATABASE`、`TRUNCATE` 或删除既有行；只运行当前任务直接相关的聚焦用例。永久跳过会重建整个 `test_db` 的 `ProjectDockerVerificationTest`。只有确实验证表结构变化时，才可在隔离测试表或临时库中重建，禁止重置共享 `test_db`。主键冲突时先定位根因，只修正夹具后重跑一次受影响用例；没有新证据时不得重复相同命令或扩跑整套测试。
- 同一迭代首次 QA 才初始化需要的测试 Schema/夹具，先核对实体主键、MyBatis 全局 ID 策略、Mapper 必读列和消息集合类型；后续复测复用已有表、数据标识和夹具，不重复搭建。夹具/Schema 错误只允许一次定位修复和一次受影响用例重跑；仍失败就把首个错误、已花时间和最小所需样例送 Harness，归为测试阻断，不能派成业务代码返修。默认纯测试命令限 120 秒，首次包含编译限 180 秒；无进度 60 秒、超预算或疑似循环立即停止，扩展预算须回 Harness 决策。命令、夹具准备、等待用户和实际测试时间分别记录；中断保持未验证，不自动重启。
- 实现与 QA 的交接同时回传本次依赖的未修改业务调用，不能把“未修改”写成“无需说明”。按 SKILL.md 的 dependencyNotes 契约记录调用位置、用途、实际覆盖/Mock/静态核对/未验证及影响；仅披露不自动扩测。
- 准确记录命令和结果；区分通过、跳过以及环境阻断。

Harness/Orca 在本机派发 Worker 时，所有 Maven 编译和测试必须经本 Skill 的 `scripts/mvn-verified.sh` 执行；该包装脚本固定 Maven 3.8.6、JDK 11.0.22、settings、本地仓库和 `nexus-private`，并在运行前校验配置。Worker 不得自行从 PATH/IDEA 重新发现或替代这些已确认值；脚本报错时作为阻断回传 Harness。

## Java 仓库习惯

遵守仓库当前的 `AGENTS.md` 和 `docs/agents/` 指引。该工作区使用 Maven，修改 Java 后按仓库要求执行格式化。若项目要求离线构建，默认保持离线；用户明确授权补依赖时，只按项目实际 settings 和本地仓库拉取缺失依赖，随后恢复离线构建和测试。私有依赖缺失时，报告具体解析错误，不得声称构建通过。
