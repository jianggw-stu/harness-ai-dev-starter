# 产物、交接与记忆

在工作跨会话/Agent、需要审计，或未来可能需要快速定位时使用。

## 最小产物

- 每个有意义的阶段优先保留一份主要产物；需要 Agent 接手时附简短交接说明。
- 不为满足模板而创建完整目录树、空占位文件或内容重复的报告。
- 交接至少说明目标、已确认决策、待解决问题、约束、相关文件/提交、验证证据和下一项获准动作。
- 长事实放在被引用的产物中，交接保持简短。多 Agent 工作不能只靠聊天历史传事实。
- 后续阶段已依赖的结论发生变化时，创建新版本或明确标记旧版本失效，不要静默覆盖。

## 持久结论与运行记录

区分两类信息：

- **持久结论**：已确认的需求、已接受的方案、证据验证过的操作事实或可复用流程。
- **运行记录**：临时假设、被否决方案、调试过程、短期 URL 或一次性工具输出。

只有用户确认、代码/数据证据或验证结果支持的观察，才提升为稳定规则；保留必要的来源以便复查。模型猜测或未经确认的讨论不能自动变成规则。

## 信息归属

- 可复用的个人研发流程放在个人 Skill。
- 产品/业务事实放在相应项目知识或代码/测试中，不混入通用研发流程 Skill。
- 临时协调和调试记录在结论及证据保留后可以清理。
- PDF、截图等展示产物可辅助说明，但不能代替结构化需求和测试证据。

## 交接核验

接手其他 Agent 的工作前，确认引用路径存在、当前分支/工作区与交接一致、关键决策和前置条件齐全。下一步动作或权限不清楚时先停下来确认，不要自行推断授权。
